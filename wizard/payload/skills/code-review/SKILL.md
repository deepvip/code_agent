# 代码评审清单

按以下四类输出，每类没有问题时写「无」。

## 1. 正确性

- 边界条件：空值、空集合、0、负数、超长输入、并发。
- 异常路径：失败时是否回滚、是否留下脏数据、错误是否被吞掉。
- 资源释放：连接、文件句柄、线程池、临时文件。
- 幂等性：重试会不会产生重复数据。

## 2. 安全

- 是否有拼接 SQL / 命令 / 路径（注入风险）。
- 用户输入是否校验与转义；输出是否转义（XSS）。
- 权限校验是否在服务端做，而不是只在前端隐藏按钮。
- 日志是否打印了手机号、身份证、token、密码。
- 反序列化、文件上传、SSRF、越权访问。

## 3. 可维护性

- 命名是否表达意图；函数是否只做一件事。
- 是否重复实现了已有的工具类/内部库。
- 是否引入了不必要的新依赖。
- 魔法数字、硬编码配置、写死的环境地址。
- 注释是否解释「为什么」而不是「做了什么」。

## 4. 测试覆盖

- 新增分支是否有对应用例。
- 是否只测了 happy path。
- 测试是否依赖外部服务或固定时间。
- 断言是否真的能失败（避免 `assertNotNull` 式假测试）。

## 输出格式

```
### 正确性
- [严重] path/File.java:42 原因 → 建议

### 安全
无

### 可维护性
- [一般] ...

### 测试覆盖
- [建议] ...
```

严重级别：`[严重]` 必须改；`[一般]` 建议改；`[建议]` 可选。
